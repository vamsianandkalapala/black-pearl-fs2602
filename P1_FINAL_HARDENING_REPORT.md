# P1 FINAL HARDENING REPORT

## Repository

BLACK PEARL FS-2602 P1 is a Python/FastAPI decision engine. Its flow is
schema validation, normalization, registered feature engineering, deterministic
Logistic Regression scoring, versioned rules, explanations, and a canonical
decision snapshot.

## Bugs Found

- H+8 was only a preparation helper; it could not retrain or register a new model version.
- Generic score serialization was missing its `json` import.
- The demo script could not print Unicode IDs on the Windows default console.
- The rule loader did not validate required rule fields, duplicate IDs, action values, or condition structure.
- The adversarial test harness initially attempted to send non-standard JSON values through an encoder that rejects them.

## Bugs Fixed

- **High — `backend/model/lineage.py`:** Added deterministic H+8 execution, new artifact/metadata/manifest generation, feature removal, and parent lineage while preserving v1.
- **Medium — `backend/model/train.py` and `backend/model/predict.py`:** Added explicit feature-list training and artifact-native prediction contracts for new model versions.
- **Medium — `backend/rules/engine.py`:** Added rulebook schema and duplicate validation.
- **Low — `backend/model/serialization.py`:** Restored the `json` import.
- **Low — `scripts/seed_demo.py`:** Made console output ASCII-safe.

## Security Findings

No obvious secret patterns were found. Applicant schemas reject unknown fields,
booleans, strings in numeric fields, non-finite values, and negatives. Model
artifacts are hash-verified. Rulebook versions are path-restricted. No hosted
LLM, external decision API, or credentials are used.

## Determinism

The same decision was repeated 100 times with one canonical byte output.
JSON key reordering and serialization/deserialization preserved results. The
deterministic fuzz test covered 300 seeded combinations.

## Model

`model_v1` remains the default Logistic Regression model with fixed seed 42,
fixed registry order, training-only median imputation, scaling, and recorded
metadata. `model_v1.joblib` was preserved. H+8 generated `model_v2` without
`repayment_history`, with new metadata, feature identity, artifact hash, and
parent lineage.

## Rules

`v1` and `v2` are JSON rulebooks with effective dates. Loading validates
required fields, version matches, date ranges, unique IDs, actions, priorities,
and supported condition operators.

## H+8

The tested prohibited feature was `repayment_history`, one of v1's top three.
The migration created v2, removed the feature, generated new hashes, and
preserved v1. The workflow was run twice in temporary directories and produced
the same artifact identity.

## Explanations

Model contributions are ranked deterministically and capped at four. Factors
are tied to registered model features and are not generated by an LLM. Full
fairness and proxy-leakage analysis remains outside P1.

## API

`/healthz`, `/metrics`, `/validate`, `/features`, `/score`, `/decision`, and
`/docs` returned HTTP 200 during the final smoke checks.

## Remaining P1 Limitations

P1 does not provide P2's persistence, full historical replay engine, or
hash-chain audit. It does not implement fairness/parity or proxy-leakage
analysis, fraud/falsified-record detection, actual watchlist screening, or
public deployment.

## P2 Dependencies

Persist the full request, response, canonical bytes, model/rule/feature hashes,
snapshot identity, and audit-chain records. Implement historical replay.

## P3 Dependencies

Implement fairness criteria, approval/error-rate analysis, and proxy-leakage
review using P1's versioned feature and decision outputs.

## P4 Dependencies

Provide public hosting, runtime configuration, and the actual watchlist
screening integration while preserving the P1 request/response contract.
